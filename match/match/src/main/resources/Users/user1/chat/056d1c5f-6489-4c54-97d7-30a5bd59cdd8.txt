1. 티빙 인턴십에 지원한 동기와, 본인이 이루고자 하는 목표는 무엇인가요? (3000자 이내)
컴퓨터공학을 전공하면서 다양한 개발 분야를 접해봤지만, 그중에서도 백엔드 개발이 저에게 가장 잘 맞는다고 느꼈습니다. 단순히 기능을 만드는 것에서 끝나는 것이 아니라, 사용자의 요청을 처리하고 데이터를 안정적으로 저장하고, 전체 시스템이 효율적으로 동작하도록 설계하는 과정이 흥미로웠습니다. 특히 구조적으로 사고하며 문제를 해결하는 과정에서 성취감을 느꼈고, 이런 경험들이 백엔드 개발자로 성장하고 싶은 목표를 더욱 분명하게 만들어주었습니다.

대학에서의 수업뿐 아니라 다양한 개인 및 팀 프로젝트를 통해 백엔드 개발의 실무 흐름을 익혀왔습니다. Java와 Spring Boot를 중심으로 백엔드 로직을 설계하고 구현해보았고, MySQL 등의 관계형 데이터베이스를 활용해 사용자 데이터를 효율적으로 관리하는 방법도 익혔습니다. 뿐만 아니라 JWT 기반 로그인 기능, 이미지 업로드 및 다운로드 처리, RESTful API 설계 등 실제 서비스에 필요한 기능들을 직접 구현하면서 개발자로서의 기본기를 다져왔습니다. 개발 과정에서는 항상 사용자 입장에서 생각하고, 확장성과 유지보수를 고려하며 코드를 작성하려고 노력했습니다.

저는 티빙이 단순한 콘텐츠 플랫폼이 아니라, 기술 기반의 미디어 서비스를 제공하는 기업이라는 점에서 큰 매력을 느꼈습니다. 수많은 사용자가 동시에 콘텐츠를 이용하고, 실시간 스트리밍, 추천 알고리즘, 사용자 맞춤형 UI 등 다양한 기술이 어우러진 환경에서 백엔드 시스템은 서비스의 핵심이 된다고 생각합니다. 특히 트래픽이 많은 서비스 환경에서 어떻게 시스템의 안정성과 성능을 확보하는지, 사용자 데이터를 어떻게 효율적으로 처리하고 분석하는지 등에 대해 배우고 직접 경험해보고 싶다는 열망이 생겼습니다. 이러한 점에서 티빙 인턴십은 저에게 매우 의미 있는 도전이자 성장의 기회라고 생각하여 지원하게 되었습니다.

이번 인턴십에서는 먼저 티빙이 사용하는 기술 스택과 개발 프로세스를 깊이 있게 배우고 싶습니다. 팀의 일원으로서 협업에 참여하면서 실무 환경에서 어떤 방식으로 문제를 해결하고 소통하는지 직접 체험하고, 실무에서 요구되는 기술 역량을 쌓는 것을 1차 목표로 하고 있습니다. 티빙의 개발 문화와 코드 리뷰, 문서화 등 실제 현업에서 중요하게 여겨지는 부분을 체득하고 싶습니다.

또한 제가 지금까지 쌓아온 경험을 바탕으로, 작지만 의미 있는 기여를 하고 싶습니다. 예를 들어 간단한 기능이나 모듈 개발에서부터 시작하더라도, 사용자의 입장을 고려한 설계와 테스트를 통해 안정적인 서비스를 만드는 데 힘을 보태고자 합니다. 실제 사용자에게 직접적으로 전달되는 기능을 구현하고, 그로 인해 더 나은 경험을 제공할 수 있다면, 그것이 저에게 가장 큰 보람이 될 것입니다.

인턴십이 끝난 후에는 단순히 지식만 얻는 것이 아니라, 실무에 자신감을 갖고 한 단계 성장한 개발자가 되어있기를 바랍니다. 더 나아가 사용자 중심의 개발을 고민하고, 기술적인 깊이를 더해가는 개발자로 계속 발전하고 싶습니다. 티빙과 같은 기술 중심 기업에서 다양한 경험을 통해 배우고 기여할 수 있다면, 저의 개발자 커리어에 있어 가장 의미 있는 시작점이 될 것이라 믿습니다.

앞으로도 빠르게 변화하는 IT 환경 속에서 새로운 기술을 계속해서 학습하고, 실무에서 요구하는 역량을 갖추기 위해 꾸준히 노력할 것입니다. 그리고 언제나 사용자와 팀을 함께 생각하는 개발자가 되기 위해 고민하고 실천하겠습니다. 이번 티빙 인턴십을 통해 그 시작을 함께할 수 있기를 진심으로 바랍니다.

2. 지금까지 학습한 프로그래밍 언어 또는 기술 스택 중 자신 있는 기술과 그 이유를 설명해주세요. (3000자 이내)
저는 Java와 Spring Boot를 활용한 백엔드 개발에 자신이 있습니다. 컴퓨터공학과에서 전공 수업을 통해 Java의 기본 문법부터 객체지향 프로그래밍 개념까지 탄탄하게 익혔고, 이후 개인 프로젝트와 국비 교육 과정을 통해 이를 실제 개발에 적용해보며 실무적인 경험도 쌓을 수 있었습니다. 특히 Java는 정적 타입 언어로 코드의 안정성과 가독성이 높고, 다양한 라이브러리와 프레임워크 생태계가 잘 갖춰져 있어, 백엔드 개발자로 성장하는 데 매우 적합한 언어라고 생각합니다.

Spring Boot는 제가 가장 많이 다뤄본 프레임워크이자, 백엔드 개발에서 실제로 서비스 가능한 기능을 빠르게 구축할 수 있도록 도와주는 도구라고 느꼈습니다. 의존성 주입, RESTful API 설계, JPA를 활용한 ORM, 스프링 시큐리티를 통한 인증 및 권한 관리, 예외 처리와 로깅 등 실무에서 필요한 다양한 요소들을 프로젝트에 직접 적용해보면서 실질적인 역량을 키워왔습니다. 또한, Spring Boot의 설정 기반 구조를 이해하면서 애플리케이션의 실행 흐름이나 빈 관리 구조 등도 깊이 있게 학습하게 되었습니다.

제가 가장 기억에 남는 경험은 ‘MEETBLOG’라는 웹 애플리케이션 프로젝트를 진행하면서였습니다. 이 프로젝트는 사용자가 자신의 학습 경험이나 기술 지식을 블로그 형태로 기록하고, 다른 사용자와 댓글을 통해 소통할 수 있는 플랫폼을 만드는 것이 목표였습니다. 이 프로젝트에서 저는 백엔드 개발 전반을 담당하였고, 로그인 및 회원가입 기능부터 게시글 CRUD, 댓글 기능, 이미지 업로드 및 다운로드, DB 설계, API 설계까지 대부분의 핵심 기능들을 직접 구현했습니다.

특히 사용자 인증과 세션 관리를 Spring Security와 JWT를 이용해 구현하면서 보안에 대한 중요성을 실감했고, 이미지 업로드 및 다운로드 기능에서는 실제 파일 저장 경로, MIME 타입 처리, 인코딩 방식 등 다양한 세부적인 기술 이슈들을 직접 마주하고 해결하면서 백엔드 개발자의 역할에 대해 더 깊이 이해할 수 있었습니다. 파일 다운로드 시 이미지가 손상되던 문제를 해결하기 위해 스트림 처리 방식과 HTTP 헤더 설정을 여러 차례 실험하며 디버깅했고, 이를 통해 문제 해결 능력과 끈기도 함께 키울 수 있었습니다.

이 외에도 프로젝트를 진행하면서 항상 단순한 기능 구현에 그치지 않고, 코드의 재사용성과 유지보수성을 고려하려고 노력했습니다. 예외 처리 로직을 공통 모듈로 만들어 코드 중복을 줄이고, JPA를 사용할 때는 N+1 문제를 방지하기 위한 Fetch 전략이나 Lazy/Eager 로딩에 대해서도 고민하며 설계를 진행했습니다. 데이터베이스 설계 역시 정규화를 고려해 테이블 구조를 짜고, 외래키 제약 조건 등을 활용해 데이터 무결성을 유지하려고 노력했습니다.

또한 Git을 이용한 버전 관리와 협업 경험도 백엔드 개발자로서 중요한 자산이라고 생각합니다. 프로젝트를 함께한 팀원과의 협업 과정에서 브랜치를 나누고, pull request를 통해 코드 리뷰를 진행하면서 협업에 필요한 커뮤니케이션 능력도 향상시킬 수 있었습니다. 프로젝트의 초반에는 역할 분담과 기능 충돌로 인한 문제가 있었지만, 정기적으로 회의를 진행하고 각자 맡은 기능을 명확히 정리하면서 효율적인 협업 문화를 만들어갈 수 있었습니다.

이러한 경험들을 통해 저는 단순히 기술을 사용할 줄 아는 수준을 넘어, 문제를 정확하게 분석하고 효율적인 해결책을 고민할 수 있는 역량을 갖추게 되었다고 생각합니다. 실제 서비스 환경에서는 수많은 사용자가 동시에 요청을 보내고, 다양한 상황에서 오류가 발생할 수 있기 때문에 백엔드 개발자는 항상 예외를 예측하고, 서비스의 안정성을 유지할 수 있는 설계와 구현 능력이 필요하다고 느꼈습니다. 이러한 점에서 Java와 Spring Boot는 안정적이고 신뢰할 수 있는 시스템을 구축하는 데 적합한 도구였고, 저도 그 기술에 대해 꾸준히 학습하고 적용해온 만큼 자신이 있다고 말할 수 있습니다.

앞으로도 새로운 기술을 배우는 데에 열려 있으면서, 현재 자신 있는 기술 스택인 Java와 Spring Boot를 기반으로 더 깊이 있는 개발자가 되기 위해 노력할 것입니다. 특히 트래픽이 많은 서비스나 실시간 데이터 처리가 필요한 환경에서 백엔드 시스템이 어떻게 설계되고 운영되는지를 더 배우고 싶습니다. 이번 티빙 인턴십에서도 제가 자신 있는 기술을 바탕으로 실무 경험을 쌓고, 더 나아가 안정적이고 유연한 백엔드 시스템을 개발하는 데 기여할 수 있기를 기대하고 있습니다.

3. 개인 프로젝트나 팀 프로젝트에서 가장 도전적이었던 문제와 그것을 해결한 과정을 기술해주세요. (3000자 이내)
MEETBLOG 프로젝트를 진행하던 중, 이미지 파일 처리 기능에서 가장 큰 도전과 마주했습니다. 이 프로젝트는 사용자가 자신의 개발 경험이나 기술 내용을 블로그 형태로 기록하고 공유할 수 있도록 만든 웹 애플리케이션으로, 이미지 첨부 기능은 사용자 편의성을 높이기 위한 핵심 요소 중 하나였습니다.

사용자가 업로드한 이미지는 서버의 지정된 경로에 정상적으로 저장되었지만, 다운로드하거나 웹 페이지에서 이미지를 불러올 때 이미지가 손상되거나 아예 표시되지 않는 문제가 반복적으로 발생했습니다. 처음에는 흔히 발생할 수 있는 파일 경로 오류나 서버의 파일 접근 권한 문제를 의심했습니다. 서버 로그를 꼼꼼히 확인하고 파일 경로 설정, 디렉터리 권한, 파일 이름 인코딩 등을 하나씩 점검했지만, 모든 설정은 예상대로 정상 작동하고 있었습니다.

문제는 생각보다 깊은 곳에 숨어 있었습니다. 오랜 시간 원인을 찾지 못하고 있던 중, 혹시나 하는 마음에 이미지 업로드와 다운로드 과정에서의 스트림 처리 방식을 비교해보았습니다. 이 과정에서 업로드 시에는 이미지 데이터를 MultipartFile로 받아 바로 저장했지만, 다운로드 시에는 파일의 바이너리 데이터를 읽어와 응답으로 전송하는 부분에서 BufferedInputStream과 OutputStream 처리 방식이 다르다는 점을 발견했습니다.

특히 다운로드 시 OutputStream에 데이터를 전송할 때, MIME 타입 설정과 Content-Disposition 헤더, 바이트 배열 처리 방식에서 문제가 있었던 것입니다. HTTP 응답 헤더에 Content-Type을 정확히 지정하지 않거나, 파일을 텍스트로 처리하는 경우 인코딩이 깨지면서 이미지가 손상된 형태로 전송되었던 것입니다. 또, 브라우저에서 파일이 바로 열릴 수 있도록 처리하지 않고 첨부 파일로 인식되도록 해야 했는데, 이 설정이 누락되면서 일부 환경에서 이미지가 열리지 않았습니다.

이 문제를 해결하기 위해 이미지 파일을 byte[]로 읽어오는 방식 대신, InputStreamResource를 활용하여 스트림 기반으로 처리하도록 변경하였고, 응답 헤더에 정확한 MIME 타입(image/jpeg, image/png 등)을 지정하였습니다. 또한, 파일 이름에 한글이 포함될 경우 브라우저 호환성 이슈가 발생하는 문제도 있어, 파일명을 UTF-8로 인코딩하고, 필요한 경우 URL 인코딩 처리도 병행했습니다. 이와 같은 개선 작업을 거친 후, 모든 브라우저와 운영체제 환경에서 이미지가 정상적으로 표시되는 것을 확인하였습니다.

이 경험은 기술적인 역량 이상의 교훈을 안겨주었습니다. 무엇보다 디버깅의 중요성과 집요함의 가치를 다시 한번 깨달았습니다. 단순히 눈에 보이는 증상만 보고 원인을 추측하는 것이 아니라, 가능성 있는 원인을 하나씩 확인하고, 실험을 통해 문제를 좁혀가는 과정이 얼마나 중요한지를 체감할 수 있었습니다. 이 문제를 해결하는 데 하루 이상을 소비했지만, 그 시간을 통해 실질적인 문제 해결 능력과 스트림 및 인코딩 처리에 대한 깊이 있는 이해를 얻을 수 있었습니다.

또한 이 과정에서 프로젝트 일정 조율의 중요성도 깨달았습니다. 문제 해결에 집중하다 보니 다른 작업 일정이 미뤄지면서 전체 진행에 영향을 줄 수 있다는 사실을 인식하게 되었고, 이후부터는 Notion을 활용하여 팀원들과의 작업 일정을 보다 체계적으로 공유하고 조율하는 방식을 도입했습니다. 매일 스크럼 형식으로 진행 상황을 공유하고, 예상되는 이슈를 사전에 공유함으로써 팀 전체의 일정 관리 효율을 높일 수 있었습니다.

이번 프로젝트에서의 경험은 단순한 기술 문제 해결을 넘어, 개발자로서의 태도와 협업 역량, 일정 관리 능력 등 다방면에서의 성장을 이끌어낸 소중한 기회였습니다. 앞으로도 이러한 경험을 발판 삼아 어떤 문제든 포기하지 않고 끝까지 파고들며, 동시에 팀 전체의 목표와 흐름을 고려할 수 있는 개발자로 성장해나가고자 합니다.

4. 티빙에서 가장 재미있게 본 콘텐츠 이름과 그 이유를 설명해주세요.
티빙에서 가장 재미있게 본 콘텐츠는 더 지니어스 시리즈입니다. 이 프로그램은 출연자들이 제한된 시간과 정보 속에서 심리전, 논리, 수학적 사고를 바탕으로 게임을 풀어나가는 형식으로 진행되며, 단순한 예능을 넘어 치밀한 전략과 인간관계를 바탕으로 한 두뇌 싸움이 펼쳐지는 점이 매우 인상 깊었습니다.

특히 매회 등장하는 독창적인 게임과 이를 풀어내는 출연자들의 다양한 접근 방식은 시청자에게도 함께 고민하고 추리하는 재미를 주었습니다. 게임의 규칙을 넘어서는 사고력과 팀워크, 때로는 배신까지 모두 게임의 일부로 녹여낸 구성은 매우 참신했고, 한 회 한 회가 짜임새 있는 퍼즐처럼 느껴졌습니다.

이처럼 시청자의 몰입을 유도하는 콘텐츠를 안정적으로 제공하고, 이를 많은 사람들이 함께 즐길 수 있도록 기술적 기반을 제공하는 티빙의 역할에 매력을 느꼈습니다. 단순한 콘텐츠 소비를 넘어, 사용자에게 '긴장감'과 '지적 재미'라는 특별한 경험을 전달하는 플랫폼의 일원으로 저도 기여해보고 싶다는 동기를 갖게 되었습니다.
